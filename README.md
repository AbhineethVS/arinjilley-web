# arinjilley?

*"Didn't you know?"* Hackathon listings for the arinjilley? WhatsApp group, as a Telegram bot and a website.

Admins forward a hackathon post to **[@arinjilley_bot](https://t.me/arinjilley_bot)**. The bot reads it with AI, makes a
boarding-pass poster and shows a preview to approve. Once published, the listing appears on
**[arinjilley.pages.dev](https://arinjilley.pages.dev)** and the bot hands back a ready-to-paste WhatsApp message.

Everything runs on Cloudflare's free plan. The only paid part is OpenAI (gpt-5-mini, under ₹0.10 a listing).
The full product spec is in [SPEC.md](SPEC.md).

## How it fits together

```
 admin ──forward──▶ Telegram ──webhook──▶ bot Worker (apps/bot) ──▶ OpenAI (reads the post)
                                              │   ▲                ──▶ Browser Rendering (poster PNG)
                                              ▼   │ BOT binding
                                          D1 database ◀── website on Pages (apps/web) ◀── visitors
                                                            └ /admin (login through the bot)
```

- **Bot** (`arinjilley-bot` Worker): grammY over a webhook. Slow steps (AI, posters) run as background jobs, with
  the Worker calling itself through the `SELF` binding. A cron runs every minute to retry anything missed, and
  once an hour it tidies old rows and checks for stuck posters.
- **Website** (`arinjilley` Pages project): server-rendered HTML from `_worker.js`, a small client bundle for
  filters and countdowns, a PWA service worker, and the admin page.
- **Database**: a single D1 database shared by both, with schema in Drizzle and SQL migrations in `migrations/`.
- **Images**: posters and thumbnails live in Telegram (by `file_id`); the site serves them through `/img/…`.
- **Alerts**: if something breaks (a failed job, OpenAI out of credit, posters stuck, a website error), the bot
  messages the owner on Telegram, at most once an hour for each kind of problem.

## First-time setup

You need Node 22+ and a Cloudflare account.

```sh
npm install                # also downloads the fonts (see "Fonts" below)
npx wrangler login
npm run secrets:init       # creates apps/bot/.dev.vars (git-ignored)
```

Open `apps/bot/.dev.vars` in an editor and paste the **bot token** (from @BotFather) and the **OpenAI key**. The
webhook and session secrets are already generated. Never paste these into chats or commit the file.

```sh
npm run db:migrate:remote  # create/upgrade the tables
npm run secrets:push       # secrets → bot Worker
npm run deploy:bot
npm run webhook:set -- https://arinjilley-bot.arinjilley-bot.workers.dev

npm run secrets:push:web   # secrets → Pages (and apps/web/.dev.vars for local dev)
npm run deploy:web
```

The secret scripts pass values to wrangler through stdin and only print key names.

## Day to day

| Task | How |
| --- | --- |
| Deploy the bot / site | `npm run deploy:bot` / `npm run deploy:web` |
| Change the database | Edit `packages/core/src/db/schema.ts` → `npm run db:generate` → `npm run db:migrate:remote` |
| Add or remove admins | `/addadmin` and `/removeadmin` in the bot (owner only), or the Admins tab on `/admin` |
| See AI spend | `/usage` in the bot |
| Change model, AI limits, prices, site or group link | `vars` in `apps/bot/wrangler.jsonc` (and `apps/web/wrangler.jsonc` for the site), then redeploy |
| Rotate a secret | Edit `apps/bot/.dev.vars` → `npm run secrets:push` and `npm run secrets:push:web` → `npm run deploy:web` (Pages only picks up secrets on the next deploy). After changing the webhook secret, also run `webhook:set` again. |
| Check | `npm run lint`, `npm run typecheck`, `npm test` |
| Watch live logs | `cd apps/bot && npx wrangler tail` |

Local dev: `npm run dev:bot` (bot, local D1 after `npm run db:migrate:local`) and `npm run dev -w @arinjilley/web`.
Telegram can't reach localhost, so bot changes are easiest to test by deploying.

## Free-plan limits worth knowing

- **Workers CPU 10 ms per request.** This is why posters go through Browser Rendering and the site is plain
  string templates. Error 1102 in the logs means something went over it.
- **Browser Rendering: 10 browser-minutes a day, one new browser every 20 s.** Each poster takes about 3–4 s, so
  that's roughly 150 posters a day. If the limit runs out, posters wait as "pending", retry every minute and go
  through after midnight UTC (5:30 AM IST). You'll get an alert if that happens.
- **AI limits** (our own, to protect the credit): 15 posts per admin per hour, 60 a day overall, posts capped at
  6,000 characters. They can be changed in `apps/bot/wrangler.jsonc`.
- **D1: 5 GB and 5M reads a day.** That's nowhere near what we use; old logins, batches and AI logs are
  cleaned up automatically.

## Troubleshooting

- **Bot doesn't reply:** check `npx wrangler tail` in `apps/bot`, then re-run `npm run webhook:set -- <url>`.
  Telegram's view: `https://api.telegram.org/bot<token>/getWebhookInfo` (open it yourself; don't share the URL).
- **"AI limit reached" / drafts filled by rules only:** see `/usage`. An alert will say if the OpenAI credit ran out
  or the key stopped working.
- **Poster stuck on "making poster…":** most likely the daily Browser Rendering minutes ran out (see above).
- **Site shows old data or styles:** pages cache for 60 s; static files are versioned on each deploy.
- **Admin login loops:** the Telegram account has to be the owner or in the admins list, and the link expires
  after 10 minutes.

## Fonts

The site and posters use **General Sans** and **Sentient** from [Fontshare](https://www.fontshare.com) and
**JetBrains Mono**. Fontshare's licence allows free use but not redistribution, so the files aren't in this repo.
`npm install` downloads them into `packages/core/assets/fonts/fontshare/` (git-ignored), and the build copies them
from there.
